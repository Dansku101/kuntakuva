## Important findings and changes

1. **Geographic identity was unverified.** The map accepted a municipality code but searched Nominatim by an independent name, then accepted the first polygon. Live Nominatim results for Kauniainen included administrative areas in Salo and Nokia. Replaced this with Statistics Finland's `tilastointialueet:kunta1000k_2026` WFS layer, queried by the three-digit `kunta` field. Require exactly one feature with matching municipality and classification year; derive bounds from its geometry. Names supplied in the request cannot override source identity. The boundary still loads before optional OSM details.
2. **Old selections could show future population grids.** Selecting a year before 2005 fell back to 2025. It now disables the grid with an unavailable explanation. Other gaps use the latest published observation no later than the selection, with its actual year displayed.
3. **Retries could reuse failed Overpass content.** An HTTP-200 response containing a timeout `remark` could enter Next's seven-day fetch cache. Overpass now bypasses that raw cache. The existing bounded process cache retains only validated successes and shares in-flight requests; failed requests are evicted. Primary/fallback order and partial-boundary behavior remain intact.
4. **External OSM website URLs were not scheme-checked.** HTML escaping alone does not make a URL safe. Server output and client links now accept only HTTP(S), without embedded credentials.
5. **Population response validation was incomplete.** Added checks for the exact returned metric and geographic/year indexes, unique dimensions and positions, complete dense arrays, and integer population counts. Wrong metrics, repeated indexes and extra/missing dimensions fail closed. Demographic charts omit missing-value bars rather than rendering zero-width substitutes.
6. **Navigation repeated content and mixed page sections with views.** Overview, Trends, Map and Statistics are now distinct URL-backed destinations. Navigation sits above the content. Municipality/year changes preserve the current view. Unneeded data requests and map initialization are avoided. The selected-year badge no longer implies that every metric is a 31 December observation from the same year.
7. **Keyboard and small-screen usability had gaps.** Search clearing returns focus to the input; active suggestions scroll into view; closed popups no longer reference a missing listbox. Scrollable chart/table regions can receive keyboard focus. Mobile targets are larger. All returned map places have a keyboard-accessible list, replacing the eight-item subset. Map zoom controls are Finnish, with a new fit-to-municipality action. Layer toggles reuse map layers. Map status no longer overlays source attribution; grid errors are separate from boundary/place errors.
8. **A population line could bridge an omitted year.** Like the other trend charts, it now splits at both null observations and nonconsecutive years. SVG tooltip strings and the existing hydration regression remain preserved.

## Product decisions

The primary audience is a resident, prospective resident, journalist or local decision-maker seeking an understandable municipality profile. The first questions are: how large is it, is it growing, what is happening to unemployment, and what does the limited financial evidence say? Specialist detail should be available without crowding that first answer.

| View | Responsibility |
| --- | --- |
| Yleiskuva | Three headline indicators, actual observation years, interpretation and routes into detail. No duplicated full charts or map. |
| Trendit | Population, employment and financial time series; chart/table controls and population export. Each series keeps its own published coverage. |
| Kartta | Geographic exploration: verified municipality identity, current mapped places and explicitly dated population grids. |
| Tilastot | Selected-year demographics and actual municipality accounts, with expandable financial definitions and sources. |

Removed the arbitrary popular-municipality footer links; municipality search remains available in every view. No new datasets or speculative indicators were introduced.

## Remaining limitations and next work

- Official boundaries are generalized at 1:1,000,000 and describe the 2026 classification, not historical or cadastral boundaries. Place inclusion close to borders is approximate; more detailed code-keyed official geometry is the next map accuracy improvement. Population tiles cover surrounding areas and are not clipped to the municipality. OSM data is current, incomplete and capped at 200 names/120 places. These limits are disclosed in the interface.
- Geography versions still differ: population 2026, employment 2025, accounts their reporting years. Do not combine them into a new cross-source indicator without harmonizing geography. Existing per-resident finance retains the documented selected-year population denominator; mergers/boundary changes need additional reconciliation before broader historical finance is introduced.
- Financial mappings remain verified only for 2024–2025. Two financial points cannot support long-term conclusions. Financial coverage is not a solvency score or investment-funding guarantee.
- Public API availability, process-local caches and multi-instance rate coordination remain operational limits. The map no longer depends on population observations, but the app still needs the municipality catalog. Failed core population requests use the page retry boundary; individual demographic/finance failures remain explicit unavailable sections. Distributed caches, rate limits and availability monitoring deserve attention before substantial public traffic.
- Population SVGs intentionally scroll horizontally on small screens to preserve readable labels. Tables are the exact-value alternative. This was a focused browser audit, not a comprehensive assistive-technology certification or all-municipality data reconciliation.
- Old `#explore-map` / `#statistics` links should be replaced with `nakyma=kartta` / `nakyma=tilastot` links. A legacy-hash redirect can be added if those links have been shared publicly.

Prioritized additions after this organization work:

1. **Compare two municipalities:** shared metric definitions and compatible geography/years, side-by-side values and percentage/percentage-point differences; no composite score. This provides context that a single municipality lacks.
2. **Age-structure trends:** extend the existing population story with published changes in children, working-age and older residents. Reuse Trends instead of creating another top-level destination.
3. **Saved municipalities:** a small local list for repeat visits, with URL sharing and no account requirement. Replaces arbitrary popular links with user-relevant navigation.

Defer news feeds, rankings and additional financial years until the core comparisons and data contracts are dependable.
